# Архитектура Companion

## Границы модулей

Python-компоненты находятся в `audio`, `stt`, `llm`, `waf` и `database`.
ROS-адаптеры вынесены в `nodes`: здесь создаются publisher/subscriber,
задаются параметры и вызываются компоненты. Такое разделение позволяет
проверять обработку аудио и текста без ROS.

Имя пакета `lwitch` сохранено. Переименование в `companion` потребовало бы
одновременно менять регистрацию ROS-пакета, импорты и пользовательские команды.

## Текущие узлы

| Команда `ros2 run lwitch …` | Вход | Выход | Поведение |
| --- | --- | --- | --- |
| `input_node` | Строки из консоли | `/stt_output`: `std_msgs/String` | Очищает некорректные Unicode-символы и публикует текст |
| `stt_node` | Файл из параметра `audio_path` | `/stt_output`: `std_msgs/String` | Однократно распознаёт файл при запуске |
| `waf_filter` | `/stt_output`: `std_msgs/String` | `/waf_output`: `std_msgs/String`, запись в БД | Проверяет текст, вызывает LLM, сохраняет результат |
| `voice_input` | Микрофон | PCM в локальной очереди и уведомление в `/voice_input` | Экспериментальный захват; очередь ещё не передаётся STT |

В `waf_filter` ответ LLM и исходный нормализованный запрос объединяются в одну
строку. Самостоятельного узла LLM или озвучивания в этой версии нет.

## Два способа работать с аудио

**Файловый путь:** `audio.record.record()` записывает моно WAV; `stt.stt`
передаёт файл Whisper и собирает текст сегментов. Этот путь используется
в примерах README.

**Потоковый прототип:** `Microphone` отдаёт копии блоков в `AudioBuffer`;
`Recorder` получает их, вызывает `AudioResampler` и `AudioChunker`, затем
складывает кадры в другую очередь. При переполнении очередь вытесняет старый
блок и увеличивает `dropped_chunks`.

Ресемплер рассчитан на текущую пару 48 → 16 кГц и усредняет группы из трёх
отсчётов. Это прототип, а не универсальный алгоритм изменения частоты.
Chunker формирует кадры по 480 отсчётов, сохраняя незавершённый хвост.

Дальнейший шаг — потребитель PCM-очереди, который собирает реплику с помощью
VAD и передаёт её STT. Silero VAD пока только анализирует отдельный файл.

## Фильтрация и хранение

Проверки идут в порядке: лимит запросов → поиск SQL-шаблонов → нормализация →
повторный поиск → LLM → запись диалога → публикация результата.

`Dialogue` хранит исходный и нормализованный текст, признак блокировки,
причину и ответ LLM. Блокировки по первому поиску SQL-шаблонов записываются
в БД; блокировки после нормализации и превышения лимита сейчас только логируются.
`timestamp` пока содержит число запросов в окне лимитера; его нужно заменить
на время события.

LLM получает только текущую реплику, без истории из БД. Идентификатор пользователя
пока фиксированный: `default_user`. Запрос к API синхронный и выполняется внутри
ROS callback. Модули LLM и БД читают окружение при импорте, поэтому настройки
должны быть готовы до запуска соответствующего узла.

Фильтр — учебный набор эвристик для текста, не полноценный HTTP WAF. Защита
SQLAlchemy при работе с БД не должна зависеть от поиска слов в пользовательской
реплике. Защита от prompt injection требует отдельного проектирования.

## Черновик сервиса

[`interfaces/CheckSafety.srv`](interfaces/CheckSafety.srv) сохранён для возможной
будущей реализации. Он не является сгенерированным ROS-интерфейсом и не подключён
к текущим узлам. Детали — в [описании черновика](interfaces/README.md).

## Что изменено при уборке

- ROS-узлы перенесены в `lwitch/nodes/`, запись файла — в `lwitch/audio/`.
- Вложенность `stt/vad/vad.py` сокращена до `stt/vad.py`.
- Удалены приветственный `main.py`, пустой `db_logger_node.py`, WAV-запись
  и вложенный список зависимостей с неиспользуемым Groq.
- Удалены старый `uv.lock` и фиксация Python 3.14. Теперь зависимости задаёт
  `setup.py`; интерпретатор выбирается под установленный ROS 2. При возврате
  к `uv lock` потребуется создать актуальный lock-файл.
- CUDA-библиотеки исключены из обязательной установки CPU-варианта.
- Исправлены старые импорты, опечатка `Recoder` и команды отсутствующих узлов.
- STT публикует текст без повторного прямого обращения к LLM; консольный ввод
  публикуется в тот же топик, который слушает фильтр.
- Личные абсолютные пути заменены аргументами и параметром `audio_path`.

Аудиокод, модель диалога, фильтры, лицензия и ROS lint-проверки сохранены.
Удалённые файлы доступны в истории Git.
